# 缺陷记录模板

实际发现缺陷后复制到 `docs/qa/defects/BUG-编号.md` 或 CodeArts 缺陷卡；本文件不是已发现的缺陷，也不计入缺陷数量。

| 字段 | 内容 |
| --- | --- |
| 缺陷编号 / 标题 | 待填写，标题写清触发条件与错误行为 |
| 来源用例 / 验证轮次 | 待填写 |
| 报告人 / 时间 | 待填写 |
| 处理人 / CodeArts 链接 | 待填写 |
| 状态 | 新建 / 已确认 / 修复中 / 待复测 / 已关闭 / 重开 |
| 严重程度 | 阻断：无法继续关键验收；严重：数据错误或丢失；一般：功能/提示异常；轻微：不影响功能的展示问题 |
| 修复优先级 | P0 / P1 / P2 / P3，说明安排理由；与严重程度分别记录 |
| 出现频率 | 每次 / 偶发，写明尝试次数与发生次数 |
| 被测仓库 / 分支 / 完整 SHA | 待填写 |
| OS、架构、Docker/Compose、浏览器版本 | 待填写 |
| Compose 项目名、数据卷、初始计数 | 待填写 |

## 前置条件与最小复现步骤

1. 待填写可复现的起始状态、服务状态和原始计数。
2. 待填写具体 URL、操作顺序；API 请求写方法/路径/请求体（凭据脱敏）。
3. 待填写观察结果的具体位置和时机。

## 预期结果

待填写，引用课程要求或已确认接口约定。

## 实际结果

待填写页面表现、HTTP 状态与响应、SQL 实际值；不要只写“不能用”。

## 证据

- 截图路径/附件：待填写。
- 日志与 SQL 输出：待填写。
- 对应时间及复现前后数值：待填写。
- 不粘贴 `.env`、密码、私钥、Token 或含凭据的远端 URL。

## 修复与复测

- 原失败版本：待填写完整 SHA，保留失败证据。
- 修复 PR / 完整 SHA：待填写。
- 复测环境、执行人、日期：待填写。
- 原用例重跑实际结果与证据：待填写。
- 相关回归用例及结果：待填写。
- 复测结论：未执行 / 通过 / 失败 / 阻塞。未复测不能仅因 PR 合并而关闭缺陷。
